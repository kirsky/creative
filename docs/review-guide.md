# Руководство для проверки

Как за пять минут пройти весь жизненный цикл задачи и где посмотреть каждое требование ТЗ.

## Сценарий

Демо уже содержит 16 задач во всех статусах. Чтобы не зависеть от них, пройдите путь с новой задачей.

| # | Кто | Действие | Что должно произойти |
|---|---|---|---|
| 1 | `dmitry` (байер) | **New task**: оффер, GEO, тип, количество, описание, референс, приоритет, дедлайн | Карточка в колонке «New» |
| 2 | `anna` (креативщик) | **My work → Pick up** (или перетащить карточку на доске) | Задача «In progress», `anna` назначена |
| 3 | `anna` | **Submit work**: файл и AI-расходы (сервис + кредиты) | «Under review», раунд 1 |
| 4 | `dmitry` | **Request revisions** с причиной | «Revisions required» |
| 5 | `anna` | Повторная сдача, снова AI-расходы | Раунд 2, «Under review» |
| 6 | `dmitry` | **Approve** | «Completed» |
| 7 | `manager` | **Dashboard** | Новая задача учтена в статусах, времени, загрузке и AI |

Перед согласованием байер может нажать **Edit brief**: каждое изменение попадёт в **Activity history** (поле, было → стало, кто и когда).

## Где что смотреть

| Требование ТЗ | Где |
|---|---|
| Время создания, взятия, сдачи, завершения | Страница задачи: панель **Facts**, блок **Time**; точные отметки в **Activity history** |
| Продолжительность выполнения | **Cycle time** (взятие → приёмка), **Queue wait**, **Review time**, **Revision turnaround** |
| AI-расходы по задаче и правкам | Страница задачи: **AI usage** в каждом раунде и итог по задаче |
| История действий и статусов | **Activity history** внизу страницы задачи |
| Загрузка сотрудников, просрочки, AI по сервисам и исполнителям | **Dashboard** (период: 7 дней, 30 дней, всё время) |

## Роли и права

Права проверяются на сервере; скрытая кнопка в интерфейсе защитой не считается.

| Действие | Байер | Креативщик | Руководитель |
|---|---|---|---|
| Создать задачу | да | нет | нет |
| Видеть задачи | только свои | пул «New» и назначенные ему | все |
| Править бриф | своей | нет | нет |
| Взять задачу / вернуть в пул | нет | да (вернуть: свою) | нет |
| Сдать работу, указать AI-расходы | нет | да (свою) | нет |
| Принять / отправить на правки | своей | нет | нет |
| Отменить задачу | своей | нет | нет |
| Дашборд | нет | нет | да |

## Статусы и переходы

`New → In progress → Under review → Revisions required → Completed`, плюс терминальный `Cancelled` (не колонка: фильтр **Show cancelled**).

| Из | В | Кто | Условие |
|---|---|---|---|
| New | In progress | креативщик | задача свободна (две одновременные попытки: одна выигрывает) |
| In progress, Revisions required | Under review | назначенный креативщик | минимум один файл |
| Under review | Revisions required | байер | причина обязательна |
| Under review | Completed | байер | комментарий по желанию |
| In progress, Revisions required | New | назначенный креативщик | вернуть в пул, история сохраняется |
| любой незавершённый | Cancelled | байер-автор | причина по желанию |

Все остальные переходы сервер отклоняет.
